Threadhold bewaart de draft alleen in dit browserprofiel. Comment blijft publiceren.

De draft staat tussen de gewone comments, op zijn eigen locatie. Bewerken opent dezelfde native editor met “Draft bijwerken”. De PR-knop Drafts is alleen navigatie. Publiceren blijft een afzonderlijke native Comment/Reply-actie.

Vormgeving gebaseerd op Microsofts gepubliceerde native commenteditor. Schematische pagina, geen screenshot van een ingelogde omgeving.

Technische richting

Een dunne laag bovenop DevOps

Native editor behouden

Een geïsoleerd content script voegt draftcontrols toe. Azure DevOps houdt zijn eigen Markdown, mentions en publicatieknop. Geen editor nabouwen.

Lokaal en duurzaam

De extension service worker bewaart drafts in extension-origin IndexedDB. Stabiele IDs, revisies en transacties beschermen tegen conflicten tussen tabs. Geen sync of PAT.

Agent-CRUD in de browser

De agent gebruikt dezelfde echte knoppen en native tekstvelden. Stabiele labels, draft-IDs en zichtbare save-resultaten. Vereist browsertoegang met de extensie geïnstalleerd.

Bestaande oplossingen, geen bewezen exacte match

Native private draft-CRUD is niet aangetroffen in de onderzochte Microsoft-contracten. vscode-pr-azdo en tuicr bieden lokale concepten, maar niet in de gekozen browser-only vorm. DevOps PR View en Markdown PR bewijzen bestaande browserintegraties, niet de volledige gevraagde draft-lifecycle.

“pending” is een afhandelstatus van een discussie, geen private draftstatus. De conclusie is een documentatiebevinding, geen bewijs dat nergens een vergelijkbare extensie bestaat.

Implementatieplan

Eerst de echte editorintegratie bewijzen

  1. Integratieproef: actuele DOM, accountcontext, inline/reply-anchors, native submit en succesdetectie vaststellen op een toegestane PR.
  2. Draft-CRUD: MV3-extensie, IndexedDB en save/read/edit/delete direct op de bestaande commenteditors.
  3. Robuustheid: SPA-navigatie, meerdere tabs, browserherstart, agentbediening en stale-locaties.
  4. Publicatieafronding: native submitguard, bewezen remote succes en behoud van drafts bij fouten/onzekere uitkomst.
  5. Distributie: Chrome/Edge-pakket, permissions- en privacydocumentatie; store-publicatie afzonderlijk regelen.
Belangrijkste grenzen: de native DOM kan veranderen; lokale drafts zijn niet automatisch versleuteld; zodra tekst in de pagina staat kan paginacode die lezen. Draft-save verstuurt geen comment. Na een onzekere publicatie wordt nooit automatisch opnieuw gepost.
Opgeleverd: onderzoek, implementatieplan en deze statische schets. Nog geen extensie geïnstalleerd of gebouwd. Volledige bronnen en acceptatiecriteria staan in docs/ van de repository. Ontwerprichting: de bestaande Azure DevOps-editor, niet een eigen huisstijl.
